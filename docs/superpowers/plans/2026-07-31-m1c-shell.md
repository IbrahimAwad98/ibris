# M1c Application Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tabs with per-tab view state, an engine priority queue favouring the
visible document, a designed empty state with recents, luminance-correct dark
mode, a command palette with a single shortcut registry, and session restore.

**Architecture:** The engine channel becomes a scanning priority queue (no new
threads, per decision 008). Tabs are implemented as snapshot/hydrate over the
*existing* stores — `viewer-store`, `search-store`, and the sidebar slice of
`ui-store` keep holding the state of the *active* tab, so `PageList`,
`PageView`, `Toolbar`, `Sidebar`, and `SearchHighlights` stay untouched. A new
`tabs-store` owns tab records, snapshots, and doc lifecycle, and persists
session state via the same `zustand/persist` mechanism `ui-store` already uses.
Dark-mode PDF inversion happens in Rust on the rendered bitmap (HSL lightness
flip, image-object rects skipped), behind an `invert` flag on render requests.

**Tech Stack:** Existing stack only, plus `tauri-plugin-dialog` (crate +
`@tauri-apps/plugin-dialog`, MIT/Apache-2.0) in Run 2. No other new deps.
Styling stays plain CSS (Tailwind is named in CLAUDE.md but has never been
installed; introducing it mid-milestone is out of scope).

## Global Constraints

- Branch `feat/m1c-shell`; Conventional Commits; commit per working step; never push.
- No new threads for PDFium work — one engine thread, priority queue only (decision 008).
- Frontend never calls `invoke()` outside `src/ipc/` (CLAUDE.md).
- No `unwrap()`/`expect()` in non-test Rust; typed `PdfError` everywhere.
- TS `strict`, no `any`; components under ~150 lines.
- `.ps1`/scripts ASCII-only; fixtures include a non-zero-origin page (decision 009).
- No synthetic keyboard/mouse verification — tests + screenshots only.
- Licence gate: `cargo deny check licenses` after any new crate.
- Full gate before declaring done: `npm run typecheck && npm run lint && npm test`, `cargo clippy -- -D warnings && cargo test` (from `src-tauri/`).

### Task 1: Engine priority queue (Rust)

**Files:**
- Modify: `src-tauri/src/pdf/engine.rs` (replace `mpsc` with a scanning priority queue)
- Modify: `docs/DECISIONS.md` (append entry 010: queue design)

**Interfaces:**
- Produces: `EngineHandle::set_active(doc_id: u64)`; `fn next_index(doc_ids: &[Option<u64>], active: Option<u64>) -> Option<usize>` (pub(crate) for tests); `EngineMsg::doc_id(&self) -> Option<u64>`.
- `EngineHandle::send` keeps its exact signature — `service.rs` compiles unchanged.

**Design:** `EngineQueue { inner: Mutex<VecDeque<EngineMsg>>, cond: Condvar, active: AtomicU64 }`
(`u64::MAX` = no active doc). `send` pushes back + `notify_one`. The engine
loop calls `recv()`, which scans for the first *hot* message — one whose
`doc_id()` is `None` (e.g. `Open`, always user-initiated) or equals `active` —
and falls back to the front of the queue (FIFO) so background work drains when
the visible document is idle. O(n) scan; the queue is tens of entries deep at
worst.

- [ ] **Step 1: Write failing unit tests** in `engine.rs` `#[cfg(test)]`:

```rust
#[test]
fn active_doc_message_jumps_the_queue() {
    let q = [Some(1), Some(1), Some(2)];
    assert_eq!(next_index(&q, Some(2)), Some(2));
}
#[test]
fn doc_less_messages_are_always_hot() {
    assert_eq!(next_index(&[Some(1), None], Some(2)), Some(1));
}
#[test]
fn fifo_within_the_active_doc() {
    assert_eq!(next_index(&[Some(2), Some(2)], Some(2)), Some(0));
}
#[test]
fn falls_back_to_front_when_active_absent() {
    assert_eq!(next_index(&[Some(1), Some(3)], Some(2)), Some(0));
}
#[test]
fn empty_queue_yields_none() {
    assert_eq!(next_index(&[], Some(1)), None);
}
```

export interface SavedView { scale: number; fitMode: FitMode; rotationDoc: Rotation;
  rotationByPage: Record<number, Rotation>; page: number; yPt: number;
  sidebarOpen: boolean; sidebarTab: SidebarTab }
